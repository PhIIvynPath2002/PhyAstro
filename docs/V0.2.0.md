# PhyAstro v0.2.0 — Earth–Moon–Sun Observation System

## Delivery And Scope

The default experience is the unified three-body space observation system.
`天球坐标仪` opens the retained v0.1.3 coordinate instrument, including its external
Earth view, geographical observer, horizontal/equatorial/ecliptic references,
probe, reference-line inspection and ground view. The two views exchange the
selected UTC instant. Their coordinate definitions are deliberately explicit;
the older direction-sphere presentation is not a physical-distance scene.

This version is a fixed-snapshot prototype. It does not propagate time during
animation. Only the camera and presentation update between user changes.

## Repository Inspection And Recovery

Before changes the repository was clean at `b2304d0`, tagged `v0.1.3`. An annotated
local checkpoint `checkpoint/v0.1.3-before-v0.2.0` retains that complete state.
The existing offline HTML and ZIP for v0.1.3 have not been replaced.

The project uses TypeScript, Vite 8, Three.js, Lucide and Astronomia. The old
Earth renderer creates a bundled Natural Earth map texture and instrument
lighting. That renderer remains in the compatibility instrument. The new space
scene uses three untextured `MeshBasicMaterial` spheres, without lighting,
shadows, atmospheric effects or other celestial objects.

The old renderer maps equatorial astronomy XYZ to Three.js `(X, Z, -Y)`. This
right-handed rotation is reused. The old sky scene has Earth radius 0.78 and a
direction-sphere radius 2.8 in illustrative units, so it could not safely become
the physical-distance scene simply by moving its projected Sun and Moon.
An incremental `core/system` and `rendering/system` extension supplies the new
model without altering the old scientific meanings. The old camera controller
only gains optional distance/fit callbacks; its original defaults are retained.

## Scientific Model

`core/system/Ephemeris.ts` calls **Astronomy Engine 2.1.19 `BaryState`** for Sun,
Earth and Moon using the same `AstroTime` object. All scientific vectors are
double-precision kilometres, measured from the **Solar System Barycenter**.
Axis orientation is **J2000 mean equator/equinox (EQJ)**: +X toward the J2000 mean
equinox, +Z toward the J2000 north celestial pole, +Y completes the right-handed
frame. This is a documented J2000 convention, not an assertion of exact ICRF.
The library's AU conversion is 149597870.69098932 km/library-AU; that constant is
recorded in snapshot metadata rather than silently replaced with another scale.

Input time is UTC. The engine approximates UT1 by UTC and derives TT with its
Espenak/Meeus Delta-T model. This is **estimated TT**, not a leap-second/EOP based
high-precision UTC conversion. Each body records its epoch, unit, frame and
`geometric` position kind. `EphemerisProvider` reserves an apparent-position
interface, but requesting `apparent` currently throws rather than returning a
mislabelled geometric result. No light-time, aberration, refraction or
gravitational-deflection corrections are applied.

Definitions of physical radius:

| Body | Radius (km) | Definition / Source |
|---|---:|---|
| Sun | 695700 | IAU 2015 Resolution B3 nominal solar radius |
| Earth | 6371.0088 | IUGG mean radius `(2a+b)/3`, WGS84 axes; spherical approximation |
| Moon | 1737.4 | NASA Moon Fact Sheet mean radius |

`Measurements.ts` checks that frames, units, epochs and position kinds match,
then computes `target − observer`, the Euclidean centre distance, a unit
direction vector and `2 asin(physical radius / centre distance)`. The latter is
returned in radians and degrees. Equal observer/target and invalid radii or
distances are rejected. All panel angles use **Observer Center**, not the camera.

## Camera And Rendering

Observer, Target and the three always-present render objects are independent.
Changing the observer translates the navigation reference and retains a
reasonable viewing direction. Changing Target never filters scene objects.
`朝向目标` aims the actual camera at that body's centre; user rotation releases
the lock while preserving the view orientation. `返回观测中心` restores the local
orbit and `系统全景` provides a wider observer-centred view.

The actual camera is outside the bodies. Its absolute SSB position and offset
from Observer Center are listed separately in the debug panel. Camera movement
uses swept segment/sphere tests, plus overlap resolution when time, centre or
scale changes. All three current display radii are considered; extreme zoom
cannot tunnel through a sphere and finish on the other side.

Every frame subtracts the camera's **double-precision scientific position** from
body centres before conversion to GPU coordinates. One render unit is 1,000,000
km; the actual render camera stays at the origin. Near/far planes are chosen
from the scene distances and logarithmic depth is enabled. These transforms
never write back to the scientific snapshot.

| Mode | Render radius | Scientific data |
|---|---|---|
| Physical Scale | Physical radius, divided by the common km/unit scale | Unchanged |
| Enhanced Visibility | Sun ×1, Earth ×12, Moon ×20; at least 6 pixel radius using actual camera distance | Unchanged |

The active mode is always shown. Enhanced radii may overlap in wide views and
are explicitly labelled `Render Radius`, not true angular diameter. Physical
and render radii are both available in each target's data section. A small body
can legitimately be subpixel in Physical Scale.

Visibility uses the **actual camera** projection, position and frustum against
the displayed spherical bounds. Angular-disc containment detects full and
partial occlusion by nearer displayed spheres. This is a basic bounding-sphere
visibility test, not pixel-perfect visibility, eclipse timing or a realistic
surface/terrain occlusion model. The panel distinguishes the scene's 3/3 body
set from each target's in-view status.

## Coordinates And Compatibility

The Earth reference overlay reuses the old reference geometry and its layer
choices. Astronomia's mean-epoch precession transforms the old **mean-of-date**
directions into EQJ before drawing them around Earth. Astronomy Engine's
true-of-date EQD rotation is deliberately not used on those mean directions.
The reference sphere remains an arbitrary annotation scale, not an orbit or
celestial distance. The geographical horizon overlay retains the coordinate
instrument's selected Earth location; it does not change the space measurement
origin from Earth Center to a surface observer.

At Sun or Moon Center the Earth overlay is hidden and the panel explains that
local Sun/Moon fixed-body grids have not been defined. The full old instrument
remains available through its separate entry. Its retained Astronomia/Meeus
Sun/Moon backend remains a lower-order compatibility model; its numerical
positions are not presented as the new SSB/EQJ engine output. The validation
report records cross-library distance differences rather than concealing them.

## Time And Offline Operation

The four default snapshots are UTC midnight on 2026-01-01, 2026-04-01,
2026-07-01 and 2026-10-01. Snapshot changes update all three body states and all
measurements together, retaining valid Observer and Target selections.

UTC, Asia/Shanghai and America/New_York are display-only choices. `Intl`
time-zone conversion handles New York DST, including the spring gap and autumn
fold. A disabled lunar-time entry reserves future work without inventing a
lunar clock. No runtime network request is needed for the ephemeris or time
display.

Run `npm ci`, then `npm run dev` for local development. `npm run build` performs
type-checking and builds the static application. `npm run build:offline --
/absolute/path/PhyAstro-0.2.0.html` creates a single classic-script HTML with all
dependencies and assets inline, after browser checks with networking disabled.
The exporter exercises both the new system and the old coordinate instrument.
The cloud browser blocks direct `file://` navigation, so validation loads the
same inline document offline; it does not claim a tested native file launch.
Actual macOS Chrome and Windows Edge were not available in this environment.

## Verification And Remaining Limits

See `validation/v0.2.0-science.md` and `.json` for all four vector snapshots,
computed distances, comparison inputs and diagnostics. **Independent JPL
Horizons comparison is pending:** the documented request failed at the network
proxy with CONNECT HTTP 403. Reference values and errors remain null. No JPL
accuracy claim is made. Cross-library consistency with the old Meeus model is
reported separately and does not substitute for independent ephemeris data.

The approximate analytical engine, estimated TT conversion, spherical bodies,
basic visibility bounds and enhanced display geometry limit precision. There
is no observational-precision or navigation guarantee, phase/illumination,
eclipse simulation, real-time integration, lunar surface frame, lunar civil
time or additional body renderer in this version.
