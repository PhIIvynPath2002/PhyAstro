# PhyAstro v0.3.0 Scientific Space Rendering Prototype

## Scope And Recovery

Incremental upgrade from v0.2.0. Git checkpoint:
`checkpoint/v0.2.0-before-v0.3.0`. Existing v0.1.3/v0.2.0 offline files and
tests are retained. No remote tag or release is published automatically.

## Scientific Data And Rendering

The immutable `SystemSnapshot`, BaryState ephemeris, physical radii, common
SSB origin, EQJ/J2000 axes, km units and estimated TT calculation are unchanged.
Input UTC approximates UT1. Positions are simultaneous geometric positions;
no light-time, aberration or atmospheric refraction. Previous independent JPL
Horizons comparison remains incomplete; see v0.2.0 science records. This
rendering upgrade does not certify ephemeris accuracy or contact times.

Pipeline: frozen scientific snapshot -> right-handed astronomy-to-render
rotation and camera-relative subtraction -> body poses and material uniforms
-> mesh projection -> actual-camera visibility -> UI.

`Illumination.ts` contains renderer-independent phase and finite solar disc
occlusion functions. Phase angle is the Sun-target-observer angle; unshadowed
illuminated disc fraction is `(1 + cos(angle))/2`. Both Camera Position and
Observer Center results are reported. Center phase is undefined for Moon
Center observing its own Moon and is shown as such, not as NaN or zero.

`BodyPose.ts` computes Earth Greenwich prime meridian from GAST in true-of-date,
rotated by EQD->EQJ, with precession and nutation from Astronomy Engine.
UTC~UT1 and no polar motion limit accuracy. Lunar pole and prime meridian
use RotationAxis's IAU elements with periodic lunar terms: approximate
synchronous rotation including model libration, not random texture spinning
or a full DE ephemeris orientation kernel. The Sun uses the library's IAU
axis model; the schematic texture is not an observed heliographic map.

## Surface Shader

Earth and Moon share a small Lambert shader. Only the Sun supplies direct
light: local physical surface point `p = normal * PhysicalRadius`; sunlight
comes from `SunPosition - BodyPosition - p`. The same snapshot provides the
blocker vector. Shadow rays and angular radii use **physical** km, independent
of mesh enhancement. No point-light shadow map or camera-mounted light.

Strict Solar has zero ambient term. Debug Ambient adds 0.035 of map radiance,
explicitly a visual aid. This is not an absolute radiometric model: no inverse
square flux calibration, spectral response, photometric BRDF, multiple
scattering, earthshine, lunar opposition surge or realistic camera exposure.
The Sun has an unlit emissive appearance (MeshBasicMaterial), independent of
the surface Lambert shader, and shares the same scientific solar position.

Each fragment computes apparent solar and blocker angular radii and separation
with atan2(cross magnitude, dot), avoiding precision loss near alignment.
Uniform solar discs are intersected in a local angular plane. A foreground
blocker can produce clear, partial (penumbra), total (umbra), or annular
illumination. This is a circle-area approximation to spherical-cap overlap,
not rigorous radiative transfer. It neglects solar limb darkening, topography,
oblateness, light-time and atmospheric effects; large angular blockers near
surfaces have less accurate penumbra boundaries. No universal numerical error
bound is claimed. Tests compare the area formula with independent numerical
disc integration and check known qualitative eclipse geometry, not contact
time accuracy. Fully eclipsed lunar surfaces go black in strict mode; no
atmospheric red-Moon effect is faked.

Camera depth occlusion uses **render** sphere positions/radii. Sun-disc
visibility for UI feedback uses physical spheres at the **actual camera**.
Surface shadows use physical sphere points. Enhanced Visibility changes only
mesh size; enhanced camera silhouettes and physical shadows need not agree.
Physical Scale is required to inspect consistent eclipse silhouettes. Phase
fraction is not the remaining brightness after eclipse or an area integration
over an enlarged mesh. Earth Center lunar occultation is just a center-ray
diagnostic; a solar eclipse on Earth is computed over its surface, not inferred
from the Earth-center row alone.

## Interaction And Navigation

Primary navigation: Celestial Instrument / Space Observation.
Only Celestial Instrument has the two submodes 天球 / 地面. Prior coordinates,
line picking, terminology tooltips, location and time controls remain intact;
its original schematic Sun/Moon rendering remains unchanged and is not
misrepresented as the new space shader. Instrument and space camera states
are saved independently in memory across view switches. Stores retain their
respective display settings. Selected snapshot time is synchronized on
switches, preserving v0.2.0 behavior.

Space keeps Observer, Target and all three Visible Bodies independent.
Near-target action is an explicit camera relocation, not an Observer change.
Swept camera constraints still guard navigation. Continuous 360-degree wheel
rotation, shift-wheel yaw, modifier-wheel zoom, pointer drag and pinch remain.
Near-target retains the current side of the target, so it does not choose a
fake illuminated hemisphere. Reset returns to Observer Center navigation.

Fixed quarter snapshots are retained; extra 2026-03-03 09:30, 11:34, 13:30 UTC
and 2026-08-12 17:46 UTC are geometric shadow experiments, not validated
contact/mid-eclipse times. Civil-zone display does not change the snapshot.

## UI Lighting

The physical Sun-to-camera direction is rotated into camera coordinates.
X/Y drive a restrained CSS highlight; forward cosine and physical solar-disc
transmission attenuate it. Exponential smoothing has a 0.18 s response time.
UI Lighting off immediately sets intensity to zero. This is artistic feedback,
not physical illumination, and cannot alter celestial science or canvas pixels.
Text and controls do not move or lose contrast. The main canvas reserves space
for the debug pane on desktop; narrow windows use an overlay below navigation.

## Resources And Performance

See ASSETS-v0.3.0.md and bundled licenses. Two 2K maps and a static 1K solar
bitmap. No runtime network, duplicate per-frame ephemerides, shadow maps or
postprocessing. Pose and illumination uniforms update on snapshot changes;
camera-dependent phase and UI direction update as navigation changes. Texture,
geometry, material and renderer resources are disposed on main-view switches.
MacBook real-device performance remains unverified; Linux SwiftShader pixel
tests are not an FPS or energy certification.

Open `PhyAstro-0.3.0.html` in recent Chrome/macOS or Edge/Windows with WebGL 2
and graphics acceleration. No npm, CDN, server, account or ephemeris API.
ZIP includes the same HTML plus documentation and texture source materials.
Actual macOS and Windows interaction and performance need user confirmation.

in the final validation report, not inferred from a successful build.
